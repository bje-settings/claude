# The commands a field test refuses to let its target run.
#
# One Python regular expression per line, matched against the whole Bash command
# with `re.search`. The comment lines directly above a pattern are its reason, and
# that reason is what the target is told when the command is blocked, so keep them
# written for the reader on the other side.
#
# The list is deliberately short. A field test observes; the only thing it stops is
# an action that cannot be undone from the transcript. Every pattern here has a
# denied sample in fixtures/field-test/commands/deny.txt, asserted one pattern at a
# time, and allow.txt holds the near misses no pattern may match. A pattern that
# stops matching, or starts matching too much, fails the suite.
#
# `(?s)` makes `.` match newlines, because a Bash call is often several lines
# joined by && or a heredoc.
#
# Every git rule steps over git's global options before the subcommand. Requiring
# the subcommand to sit next to `git` left `git -C <dir> push --force` unmatched,
# and `git -C <dir>` is exactly how a skill driving a worktree writes it. The
# options are enumerated rather than "anything starting with -": a wildcard would
# let `git --no-pager log --grep filter-repo` walk to the word filter-repo and
# refuse a read-only command.

# Force-pushing rewrites history other people may already have. --force-with-lease
# is allowed: it refuses when the remote moved, which is the case that loses work.
# The lease check is per push, not per command line: a safe push earlier in an &&
# chain must not license an unsafe one after it. A refspec with a leading `+` is a
# force push in the other spelling and loses the same history.
(?s)\bgit\s+(?:-[cC]\s+[^\s;&|]+\s+|--(?:git-dir|work-tree|namespace|exec-path)=[^\s;&|]+\s+|--(?:no-pager|paginate|bare|literal-pathspecs)\s+)*push\b[^;&|]*?(--force(?!-with-lease)\b|\s-f\b|\s\+[\w:./-]+)

# Deleting a remote branch, either with --delete or with an empty-source refspec,
# throws away the only copy of work that is not merged anywhere. Scoped to one push
# like the rule above: `.*` would let an ordinary push license a match on anything
# after it, so `git push origin main && git branch -d feature` would be refused.
# `--delete` is bounded too, or `gh pr merge --delete-branch` matches it.
(?s)\bgit\s+(?:-[cC]\s+[^\s;&|]+\s+|--(?:git-dir|work-tree|namespace|exec-path)=[^\s;&|]+\s+|--(?:no-pager|paginate|bare|literal-pathspecs)\s+)*push\b[^;&|]*?(--delete(?![\w-])|\s-d\s|\s:[\w./-]+)

# A mirror push replaces every ref on the remote with the local set, deleting any
# branch or tag this checkout does not have.
(?s)\bgit\s+(?:-[cC]\s+[^\s;&|]+\s+|--(?:git-dir|work-tree|namespace|exec-path)=[^\s;&|]+\s+|--(?:no-pager|paginate|bare|literal-pathspecs)\s+)*push\b[^;&|]*--mirror\b

# Rewriting history across a whole branch invalidates every clone and open PR of it.
(?s)\bgit\s+(?:-[cC]\s+[^\s;&|]+\s+|--(?:git-dir|work-tree|namespace|exec-path)=[^\s;&|]+\s+|--(?:no-pager|paginate|bare|literal-pathspecs)\s+)*(filter-branch|filter-repo)\b

# Recursive delete of an absolute or parent path. A field test may create worktrees
# and scratch directories under the checkout and remove them again; anything above
# the checkout is out of bounds, and a regex cannot tell where the checkout ends, so
# a rooted or upward path is refused and the user re-runs it if it was meant. The
# path may be quoted; a quote is how an agent writes one that expands.
#
# The two lookaheads find the recursive flag and the force flag anywhere in the same
# command, in either order and in any spelling, because `rm -r -f /` and
# `rm --recursive --force /` delete exactly what `rm -rf /` deletes. Both are bounded
# to the one command, so a flag belonging to a later command in the line is not read
# as part of this one.
(?s)\brm\b(?=[^;&|]*?(?:\s-[a-zA-Z]*[rR][a-zA-Z]*\b|\s--recursive\b))(?=[^;&|]*?(?:\s-[a-zA-Z]*f[a-zA-Z]*\b|\s--force\b))[^;&|]*?\s["']?(/|~|\$HOME|\$\{HOME\}|\.\.)
